## What round 3 must do

The content of round 2 is right; the **information architecture** is wrong (too many separate pages, unclear home, dumb navigation). Round 3 offers **3 clearly different navigation / home concepts**, each a complete small app in the Budget-Tank visual language (tank with fill + dashed plan line, HA-like cards, accent #03a9f4, tank blues), each showing:

1. **Startseite** with a clear job: answer „Liegen wir im Plan, und muss ich etwas tun?" — Eilmeldung on top if any, the tank (free to spend), what needs me (inbox count), next debits. State it in the design's motto.
2. The **same home without Eilmeldung** (all seen) OR the expanded event, as a second state.
3. How the user reaches Woche / Zyklus / Jahr / Töpfe **without feeling like many pages**.
4. Phone vs desktop optimisation made explicit per design: **phone = glance + quick action on the go (answer an inbox question with one tap, see free-to-spend, Eilmeldung)**; **desktop = review and planning (cycle close, year/contracts, pots donut, rules) side by side, using full width**. Everything reachable on both, but the emphasis differs. Show at least one screen per design where the desktop frame clearly uses a multi-column layout.

Three distinct directions (each genuinely different — traits must not overlap):

- **r3a „Ein Feed"** — one scrolling home; everything is a card in priority order (Eilmeldung → Tank → Fragen → Nächste Abbuchungen → Woche → Zyklus → Jahr → Töpfe); cards expand in place (no page change). Phone: single column, top cards only expanded. Desktop: masonry/2–3 column grid of the same cards, all expanded. Screens: Start mit Eilmeldung · Start ruhig (Karte „Zyklus" expanded in place) · Desktop-Überblick (if not covered by the viewport frame, otherwise a state with the pots donut expanded).
- **r3b „Zoom durch die Zeit"** — one screen with a time zoom control (Heute · Woche · Zyklus · Jahr); the tank and the list below morph to the chosen horizon; Töpfe is a toggle on the tank (Konto ⇄ Töpfe, flips to the donut). Phone: zoom as a segmented control at top, swipe between zoom levels. Desktop: zoom as a horizontal timeline header, detail panel on the right. Screens: Heute (with Eilmeldung) · Zyklus · Jahr · Töpfe-Donut.
- **r3c „Aufgaben zuerst"** — home is a short to-do / answer list ("3 Fragen", "Vertrag Fitness kündbar bis 30.11.", "Eilmeldung") above a compact tank; everything else under one „Mehr"/sidebar with 4 entries. Phone: bottom bar with 2 items (Heute, Mehr) + inline answer chips. Desktop: left nav + content + right column with the tank always visible. Screens: Heute · Frage beantworten (inline, one tap) · Plan & Jahr (desktop-focused) · Töpfe-Donut.

Wire all screens with `data-screen-link` from real controls (cards, zoom segments, nav items). Overview attributes per design: motto, exactly three genuine difference traits, icon, colour (not accent blue), overlay corner.

Carry over as fixed (identical in all three): person handling per the decision (own view = only own items; „Haushalt" toggle for shared), donut for pots coverage, calendar-year timeline with notice deadlines and the benchmark scale, chart-encoded hints instead of text hints, Eilmeldung behaviour.
